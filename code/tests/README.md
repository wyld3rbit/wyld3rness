# Harness tests

The tests of the `wyld3rness` harness. They drive it with the fakes in `code/src/wyld3rness/testing.py`, a judge, an embedder, a system under test and a world for the loop, none of them FindyFixy, so they need no model, database or network. `make test` runs them with the example app's tests. `make test-harness` runs them alone, in a throwaway environment that has no app installed, which proves the harness stands on its own.

- `code/tests/test_harness_rules.py` enforces the harness's architecture: it imports only the standard library, its declared dependencies and itself, has no import cycles or relative imports, never works out a path from its own location, and keeps the loop's verdict on the standard library only.
- `code/tests/test_attest.py` tests the CI gate on temp trees, including a workspace with two source roots and the command line run alone with no site-packages.
- `code/tests/test_runner.py`, `code/tests/test_metrics.py`, `code/tests/test_judge.py`, `code/tests/test_report.py`, `code/tests/test_stats.py`, `code/tests/test_provenance.py` and `code/tests/test_cli.py` cover the eval runner, the metrics and their judge, the report and baseline rules, the statistics, the run's provenance and the command line.
- `code/tests/test_trace.py` tests the span tree and provider with an in-memory exporter, including that a hung or refusing backend does not slow the code that makes spans. `code/tests/test_eval_tracing.py` covers eval cases as traces with their scores.
- `code/tests/test_loop.py` runs the loop through every way an incident ends (resolved on the first or a later try, out of tries, a recovery that does not hold, a failed action or undo, an action with no undo, a decider or an environment that fails) on a fake world and clock, plus a decision the policy refuses and a model call the budget refuses. `code/tests/test_verdict.py` covers the verdict: good seconds, verification, recovery that holds.
- `code/tests/test_policy.py` covers the policy table: unknown kinds, actions that must be alone, preconditions that refuse or cannot be checked. `code/tests/test_budget.py` covers the budget: the byte bound (on entry 014's measured prompts too), refusals, unpriced models and settling.
- `code/tests/test_credential.py` covers the signed claims, the token format and the OpenBao signer with a fake vault.
- `code/tests/test_remote.py` runs the loop through a decider served over HTTP on a local port: the history on the wire, budget refusals, a failing or missing agent, one decider per incident.
- `code/tests/test_prices.py` covers the price table parser and its sync to Langfuse, and `code/tests/test_langfuse_env.py` checks the Langfuse secrets writer against its compose file.
